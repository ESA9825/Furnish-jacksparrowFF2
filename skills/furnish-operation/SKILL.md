# Furnish 方案操作

以正在运行的 Furnish 桌面状态为准，通过专用 MCP 完成用户要求的操作，并交付可核对的结果与实际保存状态。工具简称均指 `furnish` MCP（当前环境名称前缀为 `mcp__furnish__`），不是 Blender 工具。使用实际发现的工具 schema，不猜参数或固定工具数量。

## 连接与任务边界

1. 先用 `get_current_plan` 获取当前户型、活动方案、家具 ID、单位、保存状态及 revision。需要完整布局、关联成员或 work 时加 `includeDetails:true`。不以磁盘 JSON 替代当前窗口状态。
2. 工具缺失、版本不一致或连接失败时用 `get_connection_status` 区分 stdio、桌面传输层及页面清单。诊断不会启动或重启窗口。需要启动时使用已知桌面入口；重启前保留未保存编辑，不擅自关闭窗口。不通过修改正式 JSON 绕过连接失败。
3. 识别用户是在只读检查、探索设计，还是明确修改当前方案。只读请求不复制或编辑；探索设计先 `copy_design` 并使用副本的新 revision；明确要求修改当前方案时在其范围内直接执行，不强制再复制或逐步审批。复制与切换会清空跨方案撤销栈。
4. 目标含糊时先从当前方案与家具记录定位；只有仍存在会改变操作对象或结果的歧义才询问。不得因当前窗口不是指定户型而编辑它。`switch_design` 只支持当前户型已有的可编辑方案，目标 designId 来自读取结果。

本技能可在没有源码仓库的桌面环境执行。仓库可用时，路径均以实际 checkout 为根，遵守其 AGENTS.md；复杂操作再阅读 `docs/MCP.md`、`docs/MCP-CAPABILITIES.md` 及对应领域文档。不要硬编码其他机器的路径。新增模型改用 `furnish-modeling`；Blender 场景／渲染按 `furnish-blender` 及已安装插件技能执行，不能把导出 GLB 说成完成渲染。

## 编辑与保存闭环

- 每次新的桌面操作按工具 schema 携带读取的 planId、最新 revision 和唯一 requestId；依赖编辑按顺序执行，成功后使用返回的新 revision。只读调用按各自 schema，不强塞写入字段。相机和文件导出也需要请求身份，但不是正式方案保存。
- 一次有共同目的的家具编辑尽量使用对应批量入口，利用整批校验、一次原撤销和原自动保存；不要用多次单件调用制造半成品。不并行发送依赖同一 revision 的写操作。
- 修改后检查完整回执，包括 MCP 错误内容中的 applied/persisted。`applied:true,persisted:false` 表示已改画布但未正式保存：停止后续写入，保留现场，报告失败与回执原因，沿界面原冲突／恢复流程处理；不重复编辑来逼迫保存。
- 超时不等于未执行。先只读核实当前状态；确需重试同一操作时沿用原 requestId、revision 和完整原参数。不能换 ID 盲目重放；页面重载后的去重缓存不保证存在，应重新核实结果。旧 revision 冲突时重读并比较变化，重新判断原意仍适用后才能构造新操作，不机械套用旧请求。
- 锁定、拖动、模态编辑、临时预览或结构保护拒绝时，依据原因处理；不自动解除锁定或绕过承重基线。需要撤销本次编辑时先核实原撤销栈，使用 `history_action` 一次 undo/redo 并检查保存，不撤销用户插入的其它操作。

## 布置与产品参数

| 目标 | 工具与操作依据 |
| --- | --- |
| 查型号并新增 | `list_catalog` 返回 catalogKey；单件或完整组合用 `add_furniture`；多件普通产品用 `add_furniture_batch`（最多100项，组合与结构动作走专用入口） |
| 调位置、机身尺寸、朝向 | `update_furniture`；依据家具 ID 修改 cx/cy/w/d/h/rot，读回实际尺寸及关联成员变化 |
| 调安装高度、镜像、开合、单灯或产品配置 | 先 `get_furniture_parameters`，再按实际支持字段与范围调用 `configure_furniture` |
| 删除 | 先确定组合及关联成员，用 `remove_furniture` 列出明确删除的 ID；工具不隐式级联，不自行扩大范围 |
| 比较、重命名或切换方案 | `compare_designs` 为只读差异；`rename_design` 不改内容且不可家具撤销；`switch_design` 先保存当前内容再切换 |

坐标与持久尺寸使用 mm；cx/cy 是模型中心，w/d 是局部宽深，h 是自身高度，rot 为度，不能从屏幕像素或屏幕左右直接推输入。左右以面对产品正面理解，并随旋转／镜像变化。安装高度与自身高度分开；mountHeight 等字段以产品返回的安装语义为准，特殊宿主／中心基准不能当成普通底部高度。未知高度不补造成厂家值。

参数嵌套对象（如 cabinet/kitchen）整体替换，先读完整配置、保留未编辑字段及稳定 ID，再提交；不是任意深合并。null 仅在工具和产品能力允许时删除可选覆盖、恢复缺省，不等于0。替换型号、升级旧柜或阵列等只写动作仅在当前产品明确提供且任务需要时使用，不自动迁移旧结构。新增精确落点不会自动吸附或避让，落地后应核对。

涉及柜体组件、建筑／吊顶、资料／采购时，按任务读取 [专项操作](references/domain-workflows.md)，不默认加载所有领域资料。

## 空间与目视复核

1. 空间编辑后使用 `measure_clearances` 检查受影响对象及相邻关系，并用 `check_space` 核对实体、完整开启空间与通道。可用 focusIds 聚焦；整组柜体、厨房或洗衣组合不能只检查主柜。范围影响无法限定或用户要求整屋时再做全案核对。纯采购／文字编辑不要求重复全屋空间检查。
2. 分开说明实际净距、算法问题、未知信息及已有人工确认。四向测距不等于最短欧氏距离；containedBoundary 仅为包络内边距，不证明柜内空腔。未知高度、资料缺失或路径可达性不会因无报错而通过；不能将模型初值当厂家安装要求，也不自动将问题标为已确认。
3. 需要视觉结论时 `get_camera` 记录视角，再 `set_camera` 到适用的2D／3D、整屋／房间／家具视角，使用 `take_screenshot` 并实际查看返回图像。核对轮廓、遮挡、门抽目标端态与关联设备；工具成功回执不代替看图。按影响选择正面、斜视或开合图，不机械要求所有视角。
4. 相机 position/target 的 x/y 为模型坐标、z 为绝对离地 mm；preset、focusIds、roomId、显式 position+target 四类取景互斥。相机不写项目或撤销栈；`configure_scene` 会修改并保存场景。临时取景若影响用户继续操作，按需要恢复原观察状态；不要恢复覆盖用户在此期间做的新调整。
5. 结束前重新 `get_current_plan` 核实活动方案与保存状态。如果期间用户或其它会话改了方案，重新判断复核证据是否仍对应当前 revision，不能以旧截图证明新状态。
