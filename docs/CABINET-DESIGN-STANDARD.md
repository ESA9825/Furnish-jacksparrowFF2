# 柜体设计规范

2026-10-28。适用于 Furnish 的柜体方案设计、模型实现与图纸核对。现有编辑／存储接口见 [柜体详细设计](CABINET-DESIGN.md)，厨房见 [厨房设计](KITCHEN-DESIGN.md)。本规范补充设计表达与验收要求；独立柜箱的本轮实现及当前1601调整见第9节，其他条目按表内能力边界处理。

本轮参考用户上一套房子的真实全屋定制 DXF，用于理解实际生产结构，不是当前1601装修的尺寸或外观依据；已交叉核对全部13个图框、文字、尺寸与5张内嵌照片，[完整理解记录](references/HONGFUYUAN-CABINETS-FULL-REVIEW.md)按组合说明各视图关系、构造和缺失资料，[案例依据](references/HONGFUYUAN-CABINETS.md)记录来源、实体句柄及用户确认。无需追问旧案是否最终下单来决定当前方案；图上未决批注仍不能作为当前施工要求。以下要求是项目设计约定；案例数值不是通用厂家要求或施工标准。

## 1. 先定义对象、基准与证据

每套柜体先明确：所在空间、用途、面对正面的左右、落地／悬挂、安装底标高及其地面基准、柜箱组合、设备位、门抽屉开向、现场障碍、需要保留的检修入口。柜体实际高、安装离地和顶封板高度分别记录，不用放大柜高代替顶封板。

尺寸与参数须带来源和状态：现场实测、图纸明确标注、图示推断、软件默认、未知／待确认。方案修改应保留原依据；不能因默认值与图纸数值相同，就把默认值标为已核实。图纸文件名中的日期不能代替图纸版本或批准日期。

参考资料中的“可以”“参考”“怎么做”“无方案”“后期沟通”分别表示建议、参考或未决问题；汇总文字中的问号和待沟通项仍保留。若立面、内部图、平面和批注冲突，列出冲突及其定位，先完成不依赖该冲突的设计，不静默选择一个版本。

## 2. 尺寸分四个层级，形成闭合尺寸链

| 层级 | 应表达的尺寸 | 核对方式 |
|---|---|---|
| 现场／安装范围 | 完成面净宽、净高、梁底、门窗、踢脚线、插座、管道；搬入与安装空间 | 和柜体外包、饰面及安装余量分别比较；未实测不判安装通过 |
| 整柜／柜箱组合 | 闭合外宽、各段深、箱体高、安装底标高、独立封板／见光板／台面 | 三视图对应同一物理边界，组合与单柜分别列总尺寸 |
| 模块／内部格 | 模块外宽及其侧板份额、内部净宽、相邻板面净高、实际可用深度 | 外宽相加闭合总宽；净尺寸按实际板件扣除，不按名称推空腔 |
| 门板／抽屉／五金 | 实际面板宽高、门缝、盖法、伸出、抽盒空间、五金范围 | 读取生产板件；面板尺寸不能代替分区宽度或抽屉内部净高 |

单位统一 mm，原小数保留；显示精度与保存精度分开。示例：案例中单门有 449.4 mm、净格有 416.4 mm，均不应先取整成 450／416 再反推整柜。

高度注明“板底”“板顶”“杆轴／杆上沿”“台面顶”“门板下沿”等参照。内部层板沿当前 `shelves[]` 基准换算，不能把 CAD 的绝对标高直接写入相对高度。保持当前地面基准与 `mountHeight` 语义，不重复叠加完成地面厚度。

外包深度、柜箱深度、门厚、背板占深和操作预留分别表达。案例餐边柜的上 350／下 450 是该案例的深度配方；不覆盖现有上下柜不同深度、冰箱框深等独立参数。

## 3. 柜箱连接、见光板与收口必须显式

先分别确定整组组合、独立柜箱、箱内隔间，再将门板／抽面映射到结构；一个箱可有多格、多门和多只抽屉。不能按每条正面分缝分箱，也不能由门数推箱数。案例电视柜三列内部对应五扇门，矮柜分隔存在单板／双板差异；厨房等宽门板与不等宽内部功能区并存。分箱依据应包含侧、顶、底板的连续关系，不能仅数竖线。

设计时先区分两种结构：

- 同一箱体内的共享隔板：现有 `moduleLayout()` 按共享板中心分配模块外宽，两端侧板计入端模块。
- 独立柜箱拼接：相邻两块侧板均为实体；见光板、收口条、顶封板若另设，应单列，不能因外观相邻自动删掉一块。

案例主卧总宽 2295、三段内部宽 416.4／866.8／867.8，剩余 144；两处内部间隔和左右端部各 36。用户已确认三个独立柜箱各用18厚侧板，左右另加18厚见光板：六块侧板108加两块见光板36，共144。两柜之间是两块18侧板，端部36是侧板18加见光板18；不能合成一块36厚板或按共享隔板套录。

一般组合的闭合关系为：`总外宽 = 各柜箱外宽之和 + 外置见光板／收口占宽`；独立柜箱外宽再扣自身左右侧板得到内部净宽。独立柜箱之间仍可做门缝、顶底及饰面对齐，但对齐不意味着共用板。共享隔板仅用于明确设计为同一柜箱的内部格，不能因模块相邻就替代独立箱体。当前方案应采用其自身尺寸、分箱和饰面选择，不直接复制旧案的2295宽、18厚见光板或三柜数量。

见光板属于成品外观和占地的一部分，收口可能有安装调节作用，两者不可与结构侧板混称。墙不直、现场余量和封板调节值未知时保留未知。不得通过无限加厚侧板或缩放全部模块来掩盖尺寸链不闭合。

当前普通柜板厚 18 mm 是软件模板／升级约定；旧案主卧侧板及两侧见光板18厚另有用户确认，不能外推图中背板、玻璃或其他区域饰面厚度。图示“加硬背”仅表达加强意图，未给出的厚度、材料和连接方式不推定。

超出单柜表达范围的整墙组合应先拆清柜箱与连接。例如案例电视柜总长 6130，超过现有普通单柜 6000 上限；此事实不构成放宽所有单柜范围的依据。按真实组合表达，并检查总长、接缝、台面连接与每个箱体。

## 4. 内部结构以使用功能决定

顶部构造另见第10节：完成高、柜箱顶、顶封板与门顶分别记录，不能把门板下退量误加到封板高度上。

固定层板、活动层板、拉条、挂衣杆、抽拉板和抽屉分别命名。不能将所有横线都识别为可移动层板，或将抽拉板简化成普通层板后声称功能已实现。层板跨格贯通与中间有隔板应按实际结构选择。

活动层板检查自身板厚、上下净高、有效深度、支承与调节范围；增加或均分层板是显式设计操作，不能替换已录入的非等距层高。案例鞋柜有 150、170、190、200 等不同层高，说明按功能分层比全柜均分更重要；这些值只用作案例核对，不作为统一鞋格规格。

鞋柜通风应分开记录活动层板退让、固定底板通风孔和外部空气路径。案例提出“活动层板内退20 mm”，但前沿还是后沿及孔径／孔距未明确；不能默认前后各减20，也不能将“有孔／有退让”判为满足通风。底板开孔、承托和清洁问题须结合实际板件确认。

衣柜先区分挂衣、叠放、外露抽屉与顶部储物区。案例“衣杆到顶60 mm”可作该方案的定位待核对值，仍须明确量到杆轴还是杆表面、参照哪块顶板以及吊装支架。挂衣杆缺失时，不以一块薄层板冒充；长短衣所需高度按用户物品核对，图纸没有给出通用人体尺寸。

案例明抽面板 225 mm 与内部层高是不同口径。多列抽屉的独立开合不意味着层高独立；记录外露／内藏、面板尺寸、抽盒及滑轨所需空间，未选五金不填写虚构净空或承重能力。

## 5. 门板、把手与五金共同决定开门

逐门段注明：无门／侧开／对开／上翻／下翻、左右铰链、盖法、门板材质、把手或开启方式、最大开启角和五金状态。开放格是结构状态；预览隐藏门板是观察状态，两者不能混用。

“无把手”“门板下沿手扣”“门板下延”“反弹器”是不同做法。案例引线明确两处门板下延 1 公分；若采用，应明确相对柜箱底板的 10 mm 伸出，并同步门板实际尺寸、闭合干涉和开启扫掠，不能仅将 `handle` 设为 `none`。置物台柜的下柜门现提供独立向下延长参数（见[适用范围与验收](ENTRY-DOOR-DROP.md)）；其他模板仍未提供通用下延构造。

大角度铰链先记录具体五金和所需开门用途。程序允许设角度不等于已选五金支持该角度；图中“左开／右开”的符号解释要与实际门轴位置核对。机器人／推车取出还应核对门板、把手及铰链侵入后的有效开口与路径，不能只检查设备静态外包。

铰链位置、活动层板排孔、层板支承及内抽轨道要做同一侧板上的位置核对。当前生产模型没有加工孔位和具体铰链体积，因此本项只能列为人工待核对，不能由现有门扇扫掠通过推导“无五金冲突”。

## 6. 踢脚、设备位、台面与包管按部件处理

踢脚／底座不是整套柜子的统一属性。案例明确 450 柜要踢脚，小推车柜不要踢脚，洗碗机踢脚尚无方案。分别确认底板是否存在、是否落地、踢脚高度与前后位置、能否拆卸、设备门是否相碰。关闭踢脚不能自动删除箱体底板，更不能将渲染底座外观解释为可拆卸施工结构。

整图内嵌照片进一步明确：落地推车由地面滚入，无底板和踢脚，门是独立侧开门；窄立抽则由门面连接带底轮的拉出框，不能混为同一种功能。灶下参考照片同时有固定承托立板和可取出的板；固定结构、抽拉功能、可拆检修板分别记录，不能看到一块横板就统一建成固定层板。照片未标尺寸／五金时保留未知。

厨房台面顶高、台面下沿、柜箱顶、门板上下沿分别标注；比较不同高度基准前先换算。图示 100 mm 抬高旁有结构疑问，不能把它变成统一踢脚高或自动抬高所有模块。

设备位分别核对本体、开口、安装散热／接口、开门和检修抽出空间。案例微波炉开放格、烤箱薄抽屉、抽拉板、碗篮及小推车是不同功能；“放得下”不证明可散热、可开门或可维修。灶下增加隔板须待灶具本体、散热和接口资料明确后定位置，不按图中一条线即判安全。

包管和建筑障碍为独立实体，参与柜箱退让、台面开口和净空检查；不要将其导出为柜体板件。柜箱、装饰板、台面、设备与建筑参考应有清楚归属，避免拆单把墙、管或参考轮廓算进柜体。

## 7. 灯带与材料需要可维护信息

灯带至少明确位置、槽／型材、出线、驱动器可达位置、开关或传感控制以及拆换路径。案例两处柜体都留有维修与开关疑问；当前发光装饰只证明视觉位置，不证明已解决布线与维护。

材料按部件区分柜箱、门板、见光板、台面、背板、玻璃与边框。案例“白框超白玻璃”与现有餐边柜的黑框展示模板不同，应作为案例要求记录；未确认前不改变所有模板和旧实例。珐琅白后的问号仍保留，型号色号与屏幕近似色分开。

案例电视柜“台面用箱体板”表明台面材料不能一律视为石材；“做直角”也不能当作所有柜子取消倒角的通用规定。

## 8. 核对输出与实现优先级

每套方案交付至少包括：闭合立面、内部结构、深度／现场关系、部件与尺寸表、门抽屉最大开启、设备及建筑障碍、未决问题和版本状态。编号应能在不同视图定位同一模块／部件。不可见的侧板、背板和顶部封板仍须可查，不能仅凭漂亮正面图通过验收。

| 设计事项 | 当前实现可复用 | 仍须补充或人工确认 |
|---|---|---|
| 尺寸、层高、分区、独立开合 | 核心模块外宽、相邻板面净高、生产门板／抽屉面板尺寸 | 图纸尺寸口径、现场基准 |
| 独立柜箱与饰面 | 普通柜支持共享／独立切换、各箱独立板件、左右见光板、顶封板和门顶退让；厨房沿原模块结构 | 侧墙收口、专用分层柜的通用切换尚未覆盖 |
| 活动板与挂衣杆 | 现有层板位置／净高编辑；显式挂衣柜模板按层板派生25mm方杆及上下门段，见[次卧柜体](SECONDARY-WARDROBE.md) | 通用杆件独立编辑、前后退让、活动排孔、实际支架和五金参数 |
| 门与五金 | 门向、逐扇状态、最大角、实际板件扫掠 | 下沿手扣／下延、大角度铰链实体、五金孔位 |
| 踢脚与设备 | 普通底座参数、厨房设备空位及实际板件检查 | 每种设备的拆卸踢脚与厂家开门关系 |
| 灯与材料 | 现有发光装饰、部分门板材质／配色 | 驱动器／检修／开关、展示框独立材质控制 |
| 制造与施工 | 可追溯生产几何及空间核对 | 封边、五金孔、连接件、承重、加工公差与现场批准 |

下一步实现顺序：先完善柜箱／饰面与尺寸链，再做层板退让及门板下延等明确几何，最后扩展五金／照明维护信息。每项先明确来源、适用模板和旧数据行为，再按现有 `product-rules`／`cabinet-core`／生产构造器路径实现，不以本次文档条目冒充已上线功能。

若新增影响几何的参数，生产构造器、`solidParts()`、二维／三维、缓存、空间确认及恢复链路须消费相同有效值；复制、替换、撤销重做、当前／命名项目往返和重复恢复按现有项目约定验收。价格和单纯配色不清除空间确认。继续保留离线运行与 `file://` 加载兼容。

初轮仅核对图纸并更新规范；后续实现与验收见下节。布局几何检查不提供加工单或施工合格结论。

## 9. 已实现的独立柜箱与1601调整（2026-10-28）

普通衣柜、储物柜、书柜等可在「整个柜体 → 结构、安装与外观 → 柜箱与见光板」选择同箱共享隔板或独立柜箱。一个现有模块对应一个柜箱；是否要合并为更宽箱体仍由原模块／配门操作显式决定。特殊玄关、餐边分层、烟机嵌合、上盖抽屉及浴室柜保留专用结构，不用通用切换覆盖。厨房模块继续使用原独立构造。

初版独立模式将每个模块作为一箱；第11节已补充连续隔间组成同一柜箱的能力，当前1637.5衣柜已从四箱调整为两箱。门板跨内部格、转角层板及局部无底等组合仍有边界；实际制造节点和五金仍需核对。详见 [完整理解记录](references/HONGFUYUAN-CABINETS-FULL-REVIEW.md)。

`cabinet.boxConstruction` 为可选 `shared/independent`；缺失按历史共享结构读取，未修改保存不物化字段，新模板继续原配置。`cabinet.endPanels={left,right}` 为可选左右厚度，mm、各0–50，仅独立柜箱可用；缺失／0均无板。独立柜箱最小外宽150与原最小净宽100同时约束，范围是软件能力，不是材料／加工要求。模式与厚度范围由 `product-rules.cabinetConstruction` 定义。

转换保持总外宽、位置、转角／镜像、模块顺序、层板和门抽配置。由共享转独立时，各模块原分配外宽保持，净宽扣各自两侧板；增加外置见光板只从相应端箱外宽扣除，不缩放其他模块。反向转换删除见光板占宽并还给端模块。改变总宽时沿原净宽比例缩放，见光板厚度保持。模块增删、改宽、排序及均分均使用同一尺寸链。

生产构造器将每个柜箱作为原普通单柜构造，保留独立顶／底／背及双侧板，见光板单独生成。柜箱内仍可能有抽屉分列短隔板；门扇数不等于柜箱数。门板范围、二维线框、空间开启、逐板实体与净距共用新布局；部件元数据映射回整柜模块编号，不将第三柜的层板误写到第一柜。未增加新脚本或保存通道。

新语义使用项目／工作区外层v26及独立v26缓存；旧格式继续读取，旧应用拒绝新外层版本。恢复、命名方案、复制、替换、撤销重做及完整cabinet缓存／确认沿原链路。替换模板不继承原柜箱构造；空间编辑使有关确认重新核对，单纯配色和采购不额外失效。

独立模式初版将当前1601的4161mm衣柜（4箱）、1637.5mm衣柜（当时4箱）、2250mm收纳柜（3箱）按原外包转换；1637.5柜后续两箱调整见第11节。层板高度、抽屉、门型、姿态及其他60件家具保持。两侧见光板暂为0：当前房屋尚无设置位置依据，不自动复制旧房18mm做法。已保留命名方案「20261028 · 独立柜箱调整前」，其内容与调整前完整工作布置一致，文件副本也保留在本机。

本轮未实现通用层板前后退让、挂衣杆／孔位、门板下延、专用分层柜的独立箱转换或灯带检修。适用回归、视觉证据、既有空间问题及全场景导出边界见 [验收记录](validation/cabinet-independent-20261028/README.md)。

## 10. 顶部封板与门顶退让（2026-10-28）

用户确认封板50mm、门顶下退10mm，并提供阳台图放大：50是柜箱上方的封板高，18是柜顶板厚，10是门顶到整体完成顶的距离。门板向上覆盖封板，不是在封板下再留10mm。三者基准明确为：

`总完成高 H = 柜箱高 B + 封板高 50`；`柜顶板顶 = B`；`柜顶板底 = B - 板厚`；`实际门板顶 = H - 10`。

门板底沿保持原值。门板相对柜箱顶上延40mm，覆盖门后的50mm封板，仅顶端露出10mm；这与“门板高减去50+10”不同。50mm来自本次确认，不是所有房屋通用安装余量。顶板18来自本案与当前板厚，软件仍按具体板厚生成。

普通柜体可选 `cabinet.topClosure={height,doorGap}`，在「整个柜体 → 结构、安装与外观 → 顶部封板与门顶退让」启用。启用输入初值50／10，旧缺失值保持无封板、原门缝；输入0退让沿用原1mm边缝。软件范围为封板0–300、门顶退让0–50mm，不代表厂家要求。封板自动采用全盖门关系，柜体总完成高与位置保持；内部层板、抽屉和门分配保留，若占满新的柜箱净高则拒绝并要求调整。常规改整柜高度仍按柜箱净高缩放内部结构，封板尺寸保持。

封板是生产板件，使用柜板厚，位于柜顶板上方、门板内表面之后；正面与柜箱前沿一致，和门内表面相接而不重叠。独立柜箱各生成一段封板，与柜箱接缝对应；共享柜箱为一段，超长时仍需加工分段设计。左右见光板若存在，覆盖整个完成高度并遮侧面。封板饰面跟随对应分区门板，模型未指定修边锯口、固定件或厂家板材幅面。

初版应用于普通衣柜、储物柜、书柜等；第12节已扩展置物台玄关、分层餐边柜及洗衣上柜的专用顶部关系。玄关洞洞板、烟机嵌合、电视上盖抽屉、浴室柜及厨房父组合仍保留专用结构；不能用统一削高代替设备净空和固定节点设计。

当前1601已应用两衣柜和高收纳柜：4161宽的完成高2450、柜箱2400、门顶2440；1637.5和2250宽的完成高2350、柜箱2300、门顶2340。其余家具及历史命名方案保留。板件、净高、面板尺寸、开启扫掠和空间确认读取同一组高度；项目／工作区v27与新缓存保护此语义，旧版本拒绝新外层格式。见 [验证](validation/cabinet-top-closure-20261028/README.md)。

封板用于现场修边，不能从一块平直模型推定房顶已平整。完成顶需按覆盖区域的最低点、完成地面及实际吊顶核对；顶铰链应落在柜箱侧板的可固定范围内，不能落进上方封板空腔。现有模型没有加工孔与铰链实体，50／10通过不等于施工条件全部满足。

本次复核还发现下列能力／设计缺口，应按实际方案继续处理：

- 分箱过细：初版“一模块一箱”的缺口已在第11节补充，1637.5柜已调整两箱四门；其他组合仍需核对功能分区、层板支承和五金，不按门数推箱数。
- 侧墙与门窗避让：侧收口宽、门板开启、把手突出、窗帘和墙面不垂直需共同核对，不能只看柜体静态外包。
- 局部底部与承托：推车位无底板／踢脚、洗碗机可拆踢脚、灶下固定承托与可拆检修板，仍不能被一项整柜底座参数替代。
- 维护与五金：灯带驱动检修、插座／管线可达、铰链与活动层板孔位、超高门稳定措施和实际滑轨选型尚无完整模型，须保留待确认。

## 11. 柜箱与箱内隔间分层（2026-10-28）

普通独立柜箱增加可选 `cabinet.boxJoints`，按从左到右的每个相邻隔间边界记录：`separate`表示两箱双侧板，`shared`表示同一箱内的一块隔板。长度为隔间数减一；缺失仍是历史“每隔间独立一箱”。连续共享边界组成一个柜箱，隔间中的层板、抽屉和门仍各自保存。全为独立时不必保存该数组。

对板厚t、N个隔间、B个柜箱：`结构侧／隔板总占宽=(N+B)×t`，每箱内部为`箱外宽=内部各格净宽之和+(格数+1)×t`。外置见光板另计。隔间的分配外宽不是柜箱外宽：同箱内边界两侧各分担半块板，箱间两侧各计一整块侧板。连接方式切换保持整柜与各隔间的分配外宽、位置、完整配置；节省或增加的板厚由相邻净宽承担，全盖门正面宽度与分缝保持。

生产构造器以柜箱为单位生成独立侧／顶／底板，箱内按隔间生成共享分隔板和相应层板；封板随柜箱分段。正面门抽及层板元数据保留全局隔间号，第二箱里的第三隔间不能误选成第一隔间。2D俯视分别画真实箱体外框与内部单隔板，3D、实体、净距及开启读取同一尺寸链。

编辑入口为「整个柜体 → 结构、安装与外观 → 柜箱内分格」，左侧结构列表标明柜箱归属及隔间号。总外宽、各箱外宽和箱内净宽需分开核对。新增／复制默认另起一箱；删除保留仍相邻的同箱关系；排序后不再连续的原同箱隔间会分箱，操作预览显示箱数变化。自动配门在各箱内进行，不跨箱重排；带分组的隔间数变化使用模块管理，同数量均分保留边界，拒绝用一次总数重建静默丢掉分箱。

当前1637.5×630×2350衣柜已改为两箱，每箱外宽818.75；四隔间和四扇门保留。原四段净宽377.875／368.875／368.875／377.875，现386.875／377.875／377.875／386.875，总计增加36。两处双板改为单隔板，纵向侧／隔板由8块变6块：四块外侧板加两块内隔板；每箱自身顶底与封板保留，共两段顶封板。50封板、10门顶退让、层板高度、门抽状态及姿态保持。其他柜体和命名方案未套用此变更。

新增分组使用项目／工作区v28与新缓存；旧v27及更早数据继续读取，未编辑不补字段，旧应用拒绝新外层版本。完整柜体配置进入缓存与空间确认；改色／采购保持原排除规则。见 [验收](validation/cabinet-box-groups-20261028/README.md)。本项解决连续箱内分格，未同时实现侧收口、铰链孔位、局部无底或灯带检修；这些仍按第10节的现场／五金依据继续处理。

## 12. 分层柜与洗衣上柜的顶部构造（2026-10-28）

置物台玄关和分层餐边柜可显式启用原 `topClosure={height,doorGap}`，沿用用户确认的50／10初值。`topClosureAvailable()`按实际结构判定能力，不开放独立柜箱转换来绕过特殊构造；`topClosureParts()`提供统一mm板件描述，生产预览与实体记录共用。特殊分层的扩展使用项目／工作区v29与新缓存，旧缺失仍不自动补值。普通柜和箱内分格原数据继续读取。

玄关只缩短柜箱顶部，上方柜门覆盖封板并距完成顶10；鞋位、置物台、中段、抽屉和下柜门的功能标高保留。零底座鞋位继续采用已确认的落地无底板结构，不因加顶封恢复最底横板。与洞洞板柜共侧板时比较实际柜箱高度；总高相同但柜箱顶不同不能自动共侧板。

餐边柜须分别读取储物上柜深和冰箱包框深，不按整柜最大深度做一条平直封板。正面封板按各段深度分段，深差超过板厚时增加交接返板，并扣掉交接处重叠；板件不互相穿插。台面、开放区、玻璃展示区和冰箱开口的宽高、深度保留，内部上界改按柜箱顶计算。封板采用全盖关系，若原柜是嵌入盖法，门抽外面板宽度随全盖更新；这不改变内部净宽。玻璃展示门仍使用原独立构造，不因顶封而改变其功能区。

整体洗衣柜的上柜沿既有附属柜结构保存封板，安装离地、总高及主柜／洗衣机／水槽保持。内层编辑器新增“当前子柜整体设置”，可直接编辑封板和门顶退让；“整个柜体”仍返回父柜。子柜保存先回父草稿，父柜保存才写入应用历史；深、高和安装离地仍按父柜原约束编辑。

当前方案应用：玄关970×350×2350，柜箱2300、门顶2340；餐边1860×630×2420，柜箱2370、门顶2410，冰箱净宽835、净高1920保留，储物上深350／冰箱段630，增加262深的18厚交接返板；洗衣上柜保持离地1800和600总高，箱高550、门顶绝对离地2390、总顶2400。当前厨房另有用户编辑，未纳入本次数据提交。历史命名方案保留。

本轮仍不自动更改烟机嵌合、纯洞洞板或厨房地柜的结构，也不据旧房照片推定当前设备散热、铰链孔位、修边和承重。返板仅说明顶部实体闭合，不代表已经逐五金检查柜体自身开门干涉。范围和证据见 [验收](validation/layered-cabinet-top-20261028/README.md)。

## 13. 侧墙收口封板（2026-11-03）

## 15. 柜箱与隔间组合的统一解释（2026-11-07）

横向组合由柜体核心boxTopology／assemblyLayout统一派生，不在界面、门板或生产模型分别从门数和字段缺省猜柜箱归属。共享、全独立及混合分箱使用同一尺寸链；可组合柜结构树显示真实柜箱／隔间归属，复制插入同箱内部时，预演明确显示被中断的原箱与新箱数量变化。

## 19. 宜家衣柜布局方法与参考尺寸（2026-11-18）

本节补充衣柜使用设计，沿用第1–8节的尺寸链、证据和制造边界。来源为宜家官方衣物收纳指南与 PAX／KOMPLEMENT 内配件介绍；适用的是使用方法与组合思路，不将宜家产品配件尺寸、连接方式或承重推广为定制柜要求。本节不修改软件默认值、旧实例或模板。

### 19.1 从物品和习惯到功能区

先盘点使用者、衣物类别、数量、实际占用空间与取放习惯，再选择柜箱及内部组件。区分挂衣、叠放、抽屉、抽拉托盘、网篮和低频储物；不先按门数均分内部。宜家示例采用双挂杆、不同高度活动层板、抽屉及挂衣下部的分隔组件，说明同一柜箱可组合多个功能。定制柜仍须按实际板件、支承跨度及五金确认构造。

- 按人分区与按物品分区均可；共用时先确认是否需要独立区及共用区，不按性别推断容量。
- 经常取用的物品安排在本人容易看见、够到的位置；可达高度由本人试取，不能只按身高或年龄套公式。顶部用于适合上置的低频轻物，重物位置结合承托及取放确认。
- 短衣多时比较上下双挂与上挂下抽；长衣需要连续净高，不在其垂落路径内强插抽屉或层板。
- 针织等易拉伸衣物优先考虑叠放；小件可用抽屉内分隔或收纳盒竖放，减少翻找。层板深度应与实际折叠尺寸相配，避免后排难取。
- 使用活动层板及可替换收纳件保留变化余地。调整范围、支承和孔位仍依实际产品；“可调整”不表示任意位置均可安装。

### 19.2 官方估算、实际设计要求与未知值分开

以下摘编自宜家《How to organise your clothes》的占用空间示意，cm换算为mm。原文明确为粗略估算，不代表衣物最大尺寸、统一安装余量或厂家要求，也不是完整功能区净高。

| 对象 | 宜家示意高度（mm） | 实际设计时的核对依据 |
|---|---:|---|
| 衬衫、罩衫 | 800 | 本人衣架挂好后的垂落长度，及取挂空间 |
| 外套 | 1000 | 实际最长外套；不能覆盖所有大衣 |
| 短连衣裙 | 1200 | 实际裙长及衣架组合 |
| 特别长的衣物 | 1900 | 实际最长衣物，不默认每柜预留同高区 |
| 挂放裤子 | 600–700 | 对折挂／全长挂及具体裤架方式 |
| 叠放10件T恤 | 250 | 实际厚度、折叠方式和可操作堆高 |
| 叠放10件毛衣 | 300 | 季节厚度与取放习惯；不据此线性外推所有衣物 |

实际方案须依次记录：物品占用尺寸及测量起止点 → 操作余量及依据 → 相邻实体表面之间的净空间 → 板厚、背板、门及五金占用 → 柜箱外尺寸。衣物垂落长度不能直接写成挂杆离地标高；挂杆到上板的取挂空间另核对。参考值只能生成待核实草案，不能自动转为现场实测或用户确认。未知数量／尺寸不按0处理，也不以参考值覆盖已有实测值。

横向容量宜直接测量日常衣物挂成一排的杆长，注明衣架、季节和是否压紧；需要估算时，用本人样本的件均占杆长乘数量，并标明估算。闭门净深用实际衣架和厚衣试放，包含门／背板／五金侵入；柜外深不等于衣物可用深。抽面高度不等于抽内净高，抽屉还须核对有效开口及完整拉出路径。

### 19.3 可选分区配方

下表为本项目据官方思路整理的概念组合，不是宜家原厂套餐或固定尺寸。各列是功能区，不强制一列一箱；分箱按结构及五金另定。顶部储物按所需容量及可达性设置，不强制全柜同高贯通。

| 适用需求 | 区域A | 区域B | 区域C | 主要取舍 |
|---|---|---|---|---|
| 短衣、衬衫较多 | 上下双挂 | 短挂＋下部抽屉 | 长挂／机动区 | 增加挂杆容量，检查上杆可达性 |
| 两人共用 | 使用者A的挂衣与抽屉 | 共用长挂／低频区 | 使用者B的挂衣与抽屉 | 独立区减少混用，宽度按实际物量分配 |
| 针织、休闲衣较多 | 短挂＋小件抽屉 | 活动层板、叠放 | 长挂＋包袋 | 增加叠放容量，控制堆高及深格难取 |
| 小空间 | 双挂区 | 长挂及剩余空间收纳 | 按余量决定，不强塞第三列 | 先保必需容量，减少过密隔板及复杂配件 |
| 取放便利优先 | 可达范围内单挂 | 易操作抽屉 | 低频区与机动层板 | 可能牺牲部分容量，须本人试取 |

## 20. 调查问卷与候选柜体方案（离线采集与直线衣柜候选已试点）

可采用“需求问卷 → 容量与约束摘要 → 2–3个有实质差别的候选 → 用户选择并调整 → 几何及现场复核”的流程。本节是后续产品设计依据。2026-11-18新增[单文件离线衣柜问卷](../tools/wardrobe-questionnaire/index.html)及[使用与回传说明](../tools/wardrobe-questionnaire/README.md)，支持选项、补充说明、尺寸依据与JSON导出／导入，先试点独立需求采集。Furnish「工具 → 问卷生成衣柜」已支持导入答卷、在户型缩略图指定区域、离线生成三种直线组件衣柜候选、生产／房间预览比较与采用；[实际支持范围和验证](WARDROBE-QUESTIONNAIRE-PLANNER.md)单列。自由说明尚未接入AI语义求解，原始答卷与候选会话未新增项目持久字段；不得将户型结构录入中的 survey 阶段误认为生活需求问卷。离线HTML不自动回传，填写者导出后通过文件传输交给设计者，其他现场图像作为独立附件核对。

### 20.1 问卷分层与回答方式

先问少量易回答的生活问题，仅对相关柜型展开尺寸与物品明细。所有数量／尺寸支持“精确值／估计范围／暂不清楚”，附单位、来源和确认状态；未知不自动选中常用答案。区分“现有数量”和“未来希望容纳数量”，避免重复叠加增长余量。默认不要求姓名、精确年龄等与设计无关的信息。

| 模块 | 建议题目与选项 | 进入设计的作用 |
|---|---|---|
| 使用对象 | 哪个房间、什么柜？几人使用？个人独立区／共用／混合？ | 确定柜型及分区归属；不由性别推断需求 |
| 日常习惯 | 更愿意挂／叠／混合？现在最不方便的三件事：找不到、拿不着、叠衣倒、抽屉少、衣物挤、其他 | 决定候选方向及软偏好 |
| 优先级 | 容量、少弯腰／少登高、少整理、预算、外观，选前三并排序；哪些必须满足？ | 分开硬约束与偏好，不用单一分数掩盖不满足项 |
| 物品盘点 | 短挂、长挂分别多少件或占多少杆长？针织／T恤多少叠或收纳盒？小件、包、被褥、箱包有哪些？ | 派生挂杆、层板、抽屉及大件容量；选择一种口径，不把件数和杆长相加 |
| 特殊尺寸 | 最长衣物挂好后多长？最大箱包／收纳箱宽深高？挂杆占用实测或样本估算？ | 确定连续净高、深度和开口，未知时给测量指引 |
| 取放能力 | 常用区是否需坐姿操作、避免弯腰或登高？本人试取的舒适高度范围？ | 约束常用杆、抽屉及层板位置；不依据年龄自动分配 |
| 当前与未来 | 换季衣物是否在此柜？未来物量维持／增加／不确定？儿童成长、共用人数会变化吗？ | 形成目标容量及可调区域；不强制统一增长百分比 |
| 现场条件 | 可用完成面宽高深及来源？门窗、床、窗帘、插座、梁、踢脚和检修位置是否已核实？ | 形成安装及操作约束；优先复用现有方案数据并标注时效 |
| 门与外观 | 平开／滑门／开放／待比较？有无把手偏好？是否已有风格选择？ | 影响可访问开口、扫掠及外观；滑门须核对实际可露出的抽屉宽度 |
| 预算与保留 | 预算含哪些项目、是上限还是目标？必须保留的柜／配件？哪些可舍弃？ | 约束替换及配置；报价缺失时只比较配件复杂度，不编造金额 |
| 特殊用途（分支） | 是否需要猫通道、保险箱、灯带、设备位？相应尺寸、路线、通风／检修依据是否已知？ | 作为独立需求核对，不因勾选即宣称承重、通风或安全通过 |

首轮可只展示使用对象、习惯、优先级、物品大类、可达需求、现场已知状态、预算与保留项；选择衣柜后再展开衣物明细。鞋柜追加鞋型与靴高，餐边柜追加餐具／电器与接口，厨房须另走设备和操作动线调查，不能直接复用衣柜参数。

### 20.2 回答如何转成方案

1. 汇总“已确认／估算／未知”的需求卡。已确认的安装范围、必须保留项、必要容量和可达限制是硬约束；挂叠偏好、配色及配件喜好用于候选排序。未实测现场只生成带条件草案。
2. 以实际占杆长、叠放／容器尺寸和大件外包推导容量，并映射为功能区净尺寸，再按第2–5节闭合实际柜箱和门抽尺寸链。记录每个区对应哪条回答及采用的估算依据。
3. 对同一需求生成2–3个可比较方案，例如“挂衣与容量优先”“取放便利优先”“少配件、便于调整”。三者必须在分区、组件或操作方式上有差别，不能只改配色；相同硬约束对每个方案均生效。
4. 候选先检查实体、门抽全行程、实际访问开口、周边障碍及软件支持范围。需求冲突或空间不足时列出缺口并请求取舍，不静默缩小长挂净高、取消必需容量或移动现场物件来制造可行结果。
5. 每个候选显示立面／内部图、净尺寸、可用杆长和容器容量、需求满足与缺口、取放代价、预算依据及待核实项。容量不确定时显示区间／条件，不输出虚假的精确适配率或未经依据的最优评分。
6. 用户选定后继续编辑，确认是采用新柜还是替换指定柜，再经现有编辑与保存链应用；问卷本身不覆盖当前布置。回答变化后标记依赖它的候选过期，保留已有人工改动及其来源。

示例：两人共用、短挂占用实测共2400mm、最长挂衣1350mm、不希望登高且必须保留小件抽屉。容量方案可比较双挂与少量层板；便利方案将常用挂杆安排在实际可达范围并减少上挂；少配件方案可比较单挂、活动板与盒。但如果可达限制被用户列为“必须”，无法够到的上杆不能计入必需日常容量，也不能靠排序分数通过。以上均为说明流程的假设输入，不代表当前1601或已验证可施工方案。

### 20.3 后续扩展与验收边界

已先试点衣柜的问卷与人工审核候选；其他柜型、完整需求求解和问卷持久化仍为后续扩展。需求到组件的派生与可行性检查放共享核心，复用现有组件树、生产构造器及空间规则；UI沿草稿与 mutate() 应用，不建立独立保存／撤销通道。若持久化问卷及来源，需单独定义最小字段、版本、旧缺失行为、导入校验、复制／替换、撤销重做、命名方案、自动保存、项目往返及候选失效规则，不能本轮文档先行宣称已支持。

后续至少验收：完整／部分／未知回答、矛盾需求、容量不足、实测替换估算、多人分配、不可达挂杆、旋转／镜像、门抽受阻、旧项目及重复恢复无漂移、取消不改现有柜、采用后撤销重做／保存刷新。维持预算和配色与空间确认的既有区分；问卷驱动的几何变化则重新核对实际受影响项。几何通过、用户可用性试取、厂家五金与现场施工确认分别报告。
