## 两份 Chromium 时间线

两轮追踪的最长绘制间隔为 299.1 和 299.4 ms。以 299.1 ms 为例，六次指针事件的 `snapMove` 分别耗时 42.9、35.6、35.5、35.8、34.8 和 36.4 ms。前五次均返回 (7130.5, 9011) mm，生产处理器因此跳过重绘。第六次变为 (7130.5, 9016) mm 后重新绘制。空档两端的 WebGL 提交 CPU 耗时为 3.9 和 4.0 ms，像素比均为 1.25。无追踪的 307.2 ms 空档也出现在同一段轨迹，表现相同。

两份 V8 CPU 采样均显示，`FurnishSnapping.move` 的主要成本集中在生成柜体吸附候选与碰撞验证（`cabinetTargets` → `volumeOverlap` → `solidParts`），以及从生产板件生成平面轮廓（`planBodyOutline` → `assemblyBounds` → `boards`）。吸附时段中，两轮样本累计分别有约 1.18 / 1.17 s 落在 `cabinetTargets` 及其子调用，约 1.06 / 1.05 s 落在 `planBodyOutline` 及其子调用。这些是整轮样本累计值。单次最重的调用出现在首个位置更新，追踪实测为 95.3 和 93.0 ms，其中也包含实体碰撞计算。

现象由主线程反复计算柜体几何和连续输入被吸附到相同位置共同造成。本次增加了拖动追踪及轨迹校验，生产吸附规则未改。
