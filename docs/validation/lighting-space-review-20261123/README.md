# 日照与整案空间核对

macOS 使用快捷方式指向的 Electron 45 桌面包，以独立端口、缓存和工作区打开同一 1601 正式存档的副本。副本含 290 件家具。正式窗口经 Furnish 本机接口只读核对案名、保存状态与空间检查。

1. **显示整案问题。** 在「项目工作台 → 使用空间检查」提交 800 mm 阈值。旧版完整列表先出现待补资料的多条同类事项，需向下滚动才能看到实体和开启问题。新版在结果顶部显示各类数量，默认展示需要处理的事项。画布侧栏在计算完成前以破折号显示计数。
2. **定位并核对。** 桌面覆盖筛选、流程中关闭对话框、无效阈值、合法阈值保存、缺资料事项定位及确认的撤销重做。正式 1601 的只读结果为 67 条，其中 58 条待处理、9 条信息不足。优先看管道包覆柜与厨房铝扣板的实体交叠、柜门抽屉及基站的正面使用空间。管道孔和缺口已经进入部分几何检查，现场仍须核实检修与开启空间。候选间隙按方向扫描，结合实际动线判断。
3. **比较暮光。** 主卧鸟瞰机位固定，在 11:30、19:00、19:15 和 20:00 比较同一场景。19:00 旧版仍接近白天，19:15 突然近黑。修改后两帧均能分辨材料和室内轮廓，19:15 的直射为零。20:00 恢复原夜间表现。目视基于实时画布，采用实际太阳位置与艺术化暮光曲线。
4. **切换照明。** 照明菜单支持键盘打开，Esc 关闭后焦点返回。主灯和夜灯各自保留设置。固定夜景可撤销重做，日照滑块在固定夜景下禁用。

同包完整存档副本中的同步点击处理由 1.72–1.74 秒降至 0.3 毫秒，修改后该次约 1.24 秒得到完整结果。此为点击回调和本次核对的耗时。单个几何步骤仍可超过分片预算。

保留同一布置和活动方案、移除测试副本中其余命名记录后，复验了主灯／夜灯分别切换、固定夜景正式保存及刷新恢复。Chrome 离线直接打开 HTML 后，通过完整空间检查及三维照明工具验证。完整工作区测试中首开主灯一次耗时约 8.8 秒，另一次超过 30 秒测试时限。对约 201 MiB 的完整副本连续操作后，出现浏览器恢复缓存提示，最后一次手动保存也未完成。阈值和核对确认在此前的完整副本测试中已完成正式保存和刷新恢复。

Node 增量回归覆盖日照、灯光预览单位、阴影、分片与撤销判定、板件实体、项目规则和测试产物保留。未运行全仓检查、窄屏、Windows 或完整 WebGPU／Cycles 出图。
