## M6 操作

Mac mini M6／24 GB，打包桌面实际使用 ANGLE Metal WebGL。四轮依次为改前、改后、改后、改前。每项真实鼠标手势发送 72 个位置，转动与平移分别执行，再拖动各房间内的单人床、净水器和马桶。表内数值为两轮各自结果，单位 ms。

| 房间（拖动物） | 旋转帧间隔 P50 改前 → 改后 | 相机平移帧间隔 P50 改前 → 改后 | 有效拖动输入到 WebGL 提交 P95 改前 → 改后 |
| --- | --- | --- | --- |
| 次卧（单人床） | 16.2 / 16.6 → 16.4 / 16.5 | 16.6 / 16.6 → 16.7 / 16.6 | 37.2 / 37.8 → 37.4 / 37.8 |
| 厨房（净水器） | 16.6 / 16.6 → 16.6 / 16.7 | 16.7 / 16.6 → 16.7 / 16.7 | 28.8 / 28.9 → 29.1 / 29.2 |
| 卫生间（马桶） | 16.7 / 16.7 → 16.6 / 16.6 | 16.6 / 16.6 → 16.7 / 16.7 | 33.6 / 33.8 → 34.5 / 34.3 |

四轮各有 40、71、45 次有效位置更新。次卧旋转有偶发长帧，P95 改前 35.0／37.7 ms，改后 35.0／39.6 ms。次卧和卫生间的拖动仍有超过 50 ms 的绘制间隔，其中包含吸附导致位置不变、无需重绘的间隔。输入到实际 WebGL 提交未包含显示合成时间。

另用同机位真鼠标拖动厨房整套 L 型地柜。基线与当前版各有 44 次有效位置变化，输入到提交 P95 分别为 719.2 和 717.6 ms，吸附计算中位耗时分别为 690.2 和 695.3 ms。该特例在原版就有明显卡顿，保留原吸附逻辑。复现时将厨房的目标换为 `fmv9dos7j1`，令 `FURNISH_RASTER_RUNS=before,after`。
