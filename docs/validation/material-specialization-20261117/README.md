# 场景材质特化验证（2026-11-17）

本轮按用户要求先做本机同场景对照，不降低精细档画质或修改实际材质参数。实验只通过隔离桌面的测试路由提供候选着色器，生产渲染器、供应资产哈希及正式方案保持原样。

## 已有 Three.js 接入

Furnish 已使用 Three.js：`index.html`约609行将r160以base64 import map内联，624行附近按需import，用于主编辑场景；`src/render/lighting-preview.js`第2行从本地vendor导入r187 WebGPU版，并配合three-gpu-pathtracer 0.0.28。不是缺少Three.js依赖，也不依赖运行时CDN。独立版本图保留原离线／主编辑兼容约束，未合并两套Three对象。

## 材质清单与保护条件

读取生产GLB导入后、交给光追器前的实际完整场景，含镜头外网格和全部材质槽。首组1410个材质实例：20个清漆材质、3个透射材质；sheen、虹彩、各向异性、色散均无正值或相应贴图。清漆、透射、基色、金属度、粗糙度、法线、曝光、光源和几何均保留。正值、贴图或未知／非有限参数会保守保留功能；各向异性旋转等辅助参数也做有限性检查。不会把当前场景缺少某功能推广成产品不支持该功能。

候选一只把BSDF求值／采样／PDF构造中已知未使用的SurfaceRecord标量读改成常量零；候选二扩展到表面记录构造、未用贴图索引和未用色散，保留原结构布局、原随机维度及状态；候选三再将整场景完全不存在的纹理槽位折叠为原索引哨兵-1，按精确字段名匹配，不能误改贴图变换或其他字段。所有替换均为临时测试模块；不是修改材质值来提速。

## 对照协议

复用`test-progressive-profile-ui`：同一份GLB字节、公有相机快照、1200×674／256采样、8反弹／16透明反弹、原ACESToneMapping曝光与同一OIDN权重。每组原版→候选→候选→原版，覆盖独立iframe初始化、场景准备、着色器编译、采样和降噪。比较原生PNG解码后的像素差，并记录原版自身重复差异。不同组不能只挑最快单次拼成提升比例。

## 已完成结果

- 只特化BSDF：`progressive-profile-Rpz3Ia`。原版52.183／47.519秒，候选51.493／50.030秒；均值49.851→50.762秒，未见收益。候选平均像素差0.086–0.088/255，原版重复差0.088/255。
- 扩展至表面与色散：`progressive-profile-iVYV1F`。原版48.676／46.799秒，候选45.382／45.724秒；均值47.737→45.553秒，单组约4.6%改善。候选平均像素差0.087–0.089/255，原版重复差0.088/255；最大像素差均约14/255。

- 完整特化＋未用纹理槽位：`progressive-profile-hFpFVu`。原版47.717／48.837秒，候选44.266／45.266秒；均值48.277→44.766秒，单组约7.27%改善。候选平均像素差0.085–0.086/255，原版重复差0.085/255，最大差11–15/255。
- 当前实际贴图：188个材质用基础色贴图、9个用bumpMap、60个用粗糙度／金属度贴图、3个用发光贴图；这些都保留。不存在normalMap，不等于删除几何法线；顶点法线和实际凹凸效果不改。

汇总见[results.json](results.json)。厨房同机位单组`progressive-profile-3fc0Nt`：55.733→53.476秒，约4.05%；平均像素差0.177/255、最大12/255，材质清单与原版完全一致。该机位不与客厅均值混算。实际打开两机位前后PNG，检查玻璃透视／反射、冰箱表面、台面、墙砖、窗帘和灯带，没有观察到新增的明显效果变化；夜景厨房较暗，未据此认证全部照明环境或全型号材质。两次重复不足以提供统计置信区间，不能承诺固定倍率或跨场景收益。小平均差不等于对所有场景的画质认证，清漆／玻璃等实际功能必须由保留规则和可见区域共同检查。

## 检查范围

`test-progressive-material-specialization`覆盖全场景清单、镜头外／贴图／未知参数保留、只读字段匹配、字段后缀边界、TSL插值、原随机状态保留、表面构造左值不改及实际贴图槽位保留。检查改动脚本与临时生成ESM语法和差异空白。实际GPU各组完整采样结束并生成PNG；全部14帧实际GPU精细档渲染通过并留存原生PNG（3组ABBA＋厨房2帧）。清单完全一致和平均像素差≤0.5/255的检查通过；已完成的前三组另按同一验证函数回读复验。test-progressive-view、test-lighting-preview也通过。未改生产模块，因此未重复正式UI／file加载或项目保存链路。

未运行全量check、其它GPU／场景或长期压力。没有把实验shader路由加入正式页面、修改vendor发布器或持久数据格式。

本轮按“先验证”交付测试候选和证据，未启用正式渲染。最终客厅约7.3%、厨房约4.0%，属于小幅收益；不是之前优化幅度的简单相加，也不保证未来场景同幅提升。
