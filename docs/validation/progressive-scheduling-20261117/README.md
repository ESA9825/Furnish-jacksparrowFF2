# 渐进观察同画质调度优化（2026-11-17）

本轮不再降低任何画质档位。沿用800px／64和1200px／256预算，独立高清的1200px／128与1920px／1024也保持；8次反弹、16次透明反弹、光源／曝光、材质、相机、分辨率、OIDN权重与分块均未修改。使用公有frameBudget／targetFrameTime配置100万初始path-step预算和32ms自适应目标，继续保留GPU计时、硬件自适应、原采样速度／GPU耗时降档及交互暂停。没有修改供应库、项目数据、保存通道或加载依赖。

预览直接使用WebGPUPathTracer自身用于判断收敛的progress.samples，不再每1.3秒另外提交GPU归约／回读。显示进度仍按1.3秒节流；pause、已完成和旧场景消息过滤沿原逻辑，完成仍等待原OIDN及GPU队列。

## 对照方式

`test-progressive-scheduling-ui.cjs --desktop-only`调用既有打包桌面隔离验收器。实际生产GLB只取一次，再给各次独立iframe发送相同副本；同一相机、夜景、完整工程、1200px／256采样。计时覆盖iframe准备、BVH、编译、采样及降噪。每轮读取最终原生PNG，并用浏览器解码比较像素。默认before→after→after→before检验顺序及重复噪声；`FURNISH_PROGRESSIVE_BENCHMARK_REPEATS=1`可只跑一组。`FURNISH_PROGRESSIVE_BASELINE`可指定保存的原版模块；未指定时对照同一模块的默认调度，统计复用共同启用。正式源文件先固定为独立输入副本，避免另一会话的正式保存影响哈希断言；测试不操作正式窗口。

同采样的随机路径／GPU调度不要求逐像素完全相同。初始严格max<16的断言碰到个别像素差20而未通过；实际平均差约0.09/255。随后加入原版自身重复渲染，平均差同样约0.09/255。最终用平均差≤0.5/255并对照原版重复差异，结合实际看图；这个近似一致性检查不能代替所有场景的画质验证。

## 未采用的试验

- 100万／32ms初试：约47.97秒→46.75秒，仅约2.5%；严格单像素门限未通过，不能把该轮标成完整验收通过。
- 固定400万预算、关闭自适应：`progressive-scheduling-ssrjYu`，原版47.477／46.665秒，候选46.061／45.988秒。只约2.2%，而GPU单帧约134–150ms，高于原来的约16ms，可能触发原100ms慢GPU策略，不采用。平均像素差0.079–0.088/255，原版重复差0.089/255。
- 关闭GPU诊断计时与固定大批次的后续试验取消，未取完整结果，不发布。该隔离进程未响应TERM后按核对PID停止，未涉及正式窗口。

首轮测试遗漏公有相机快照而失败，已修复；首次断言源正式文件哈希变化来自另一个会话正常保存，随后使用固定输入副本，不将其归为应用写坏正式文件。

最终保留自适应100万／32ms的对照通过（`progressive-scheduling-K8OdO3`）：原版49.159秒、优化版46.292秒，单组约5.8%；平均像素差0.08975/255、最大14/255，实际查看最终PNG，轮廓、吊顶光带、接缝与暗部没有观察到新增缺失或明显劣化。GPU帧平均约15.9ms→30.1ms，优化版最大33.4ms，未触及100ms降档阈值。结合初试约2.5%，本轮只能说明小幅改善，不保证稳定倍率或其它场景收益。

`test-progressive-view`、`test-lighting-preview`及改动脚本语法检查通过。`test-progressive-view-ui`三入口通过（`progressive-view-ESXlGF`）：真实采样、相机复用、暂停恢复、编辑辅助、灯光重建、独立预览互斥、偏好、file／无WebGPU回退和390px；`test-lighting-preview-ui --desktop-only`通过（`lighting-preview-Bgbf8W`）：实际128采样OIDN PNG、关闭／移动灯具及复制方案失效、取消、GPU资源释放、无WebGPU负例、窄屏与Cycles入口。未重复1024采样精细PNG，因本次不改画质分支。未运行全量check、其它GPU／低配实机、长期显存压力或全型号模型验收。主要耗时仍是完整路径追踪，调度优化不等于光追算法本身获得倍数加速。
