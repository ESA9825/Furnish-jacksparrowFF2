# 1601 分房间窗光与主卧验收

2026-11-21。将客餐厅的实时窗光与接地阴影推广到 1601。主卧用两组正常站姿的同机位实测，每个机位单独取改前和改后截图。对照基线为已采用客餐厅效果的 `3fb0f5e5`。

## 窗光与接地

- 主卧睡眠区取南侧飘窗 `cad_window_11_5:front`，净宽 1971 mm，窗台 647 mm，窗顶 2295 mm。阅读区取北窗 `cad_window_8_2`，净宽 1454 mm，窗台 955 mm，窗顶 2307 mm。用生产洞口确定入光面和朝向，分别按窗宽、窗高和离窗距离衰减。
- 同一套渲染路径读取次卧飘窗、厨房侧窗、卫生间窗，以及客餐厅连通阳台的主窗和侧窗。走廊和玄关只接收原有场景光及适用家具的接地阴影。预览窗光范围来自 1601 的房间边界和窗洞引用，窗帘对漫射光的遮挡和多次反弹只保留既有渲染的表现。
- 一张 192 × 192 纹理储存各位置的照度权重，每个位置最多计算两扇相关窗。窗外底色共用一个实例网格，各房间的接地阴影共用另一个实例网格。接地阴影取床架、柜体、桌椅等生产模型的低位支承件，按已知地面高度绘制，拖动后更新。夜间使用既有夜景和减弱的接地阴影。
- 使用 WebGL 的「流畅观察」。项目字段、家具尺寸和位置、光追及生产导出范围沿用原机制。

## M6 桌面实测

Mac mini M6／24 GB，实际打包 Electron 与 ANGLE Metal WebGL，完整 248 件家具。采用改前、改后、改后、改前的顺序。每个手势发送 72 个真实鼠标位置，分别旋转相机和拖动主卧双人床。

| 指标（ms） | 改前两轮 | 改后两轮 |
| --- | --- | --- |
| 旋转绘制帧间隔 P50 | 16.1 / 16.0 | 16.5 / 16.6 |
| 旋转绘制帧间隔 P95 | 45.5 / 37.1 | 29.5 / 18.5 |
| 拖动绘制帧间隔 P50 | 35.6 / 37.5 | 37.1 / 36.8 |
| 拖动绘制帧间隔 P95 | 99.4 / 99.3 | 107.4 / 99.6 |
| 改变床位置的指针输入到 WebGL 提交 P95 | 34.7 / 36.9 | 36.3 / 36.4 |

四轮各有 48 次拖动输入实际改变床的位置。拖动帧间隔也包含吸附后位置不变、无需重绘的间隔。每轮拖动均有 13 个超过 50 ms 的绘制间隔，输入到提交时延相近。旋转尾部在不同轮次波动，四轮均出现超过 50 ms 的帧间隔。固定睡眠区机位由 328 次绘制调用增至 329 次，增加 142 个三角形。

复现使用 `scripts/verify/verify-living-furniture-raster.cjs`，基线参数 `3fb0f5e5`，`FURNISH_RASTER_RUNS=before,after,after,before`，`FURNISH_RASTER_TARGETS=fmv3vyflm1,fmv3w361v2`，用 `FURNISH_RASTER_CAMERA` 和 `FURNISH_RASTER_SECOND_CAMERA` 传入上表两个机位的 JSON（`mode: "orbit"`，`position` 与 `target` 为 x/y/z，另传 `horizontalFov`）。

## 验收范围

- 增量验证覆盖房间隔离、主卧两端窗的衰减、侧向窗、无外窗房间、接地与遮挡层开关、家具抬高、夜景、清理、窗洞尺寸、飘窗、遮阳模型、阴影缓存、观察图层、太阳位置与照明规划。
- 主卧桌面验证覆盖实际截图查看、真实指针输入、无 WebGL 着色器错误、撤销／重做及保存刷新。床和床头柜的生产 GLB 含 36 个节点。其他房间随实际窗洞启用，逐房间目视及独立性能测试留待后续使用中核对。
- 本轮未运行全套检查、窄屏桌面验收或光追。正式 1601 文件的 SHA-256 验收前后相同，操作和保存只作用于隔离副本。测试应用已关闭，可再生成的测试资源已按归属清理，保留截图、测量和验收副本。
